# Package Manager Rules

## Python: Always Use `uv`

**CRITICAL**: For ALL Python-related operations, ALWAYS use `uv` as the package manager. NEVER use `pip`, `pipx`, `poetry`, `conda`, or any other Python package manager.

### Python Installation
- Use `uv python install <version>` to install Python versions
- Example: `uv python install 3.10` or `uv python install 3.11`

### Python Package Installation
- Use `uv pip install` for installing packages
- Use `uv pip install --system` for system-wide installation
- Use `uv pip install -e .` for editable installs
- Use `uv sync` when `uv.lock` exists
- Example: `uv pip install --system --python 3.10 --no-cache -e .`

### Python Dependency Management
- Use `pyproject.toml` for project configuration
- Use `uv.lock` for lockfile (generated by `uv lock`)
- Always run `uv lock` after adding dependencies
- Use `uv pip compile` for requirements.txt generation if needed

### Docker/CI/CD
- In Dockerfiles, install Python via `uv python install <version>`
- Install dependencies with `uv pip install`
- Never use `apt-get install python3` or `pip install` directly
- Create symlinks from uv's Python to `/usr/local/bin/python3` and `/usr/local/bin/python`

### Examples
```bash
# ✅ CORRECT
uv python install 3.10
uv pip install --system -e .
uv pip install torch diffusers

# ❌ WRONG
pip install torch
python3 -m pip install torch
apt-get install python3.10
```

## Node.js: Always Use `bun`

**CRITICAL**: For ALL Node.js/npm-related operations, ALWAYS use `bun`. NEVER use `npm`, `pnpm`, `yarn`, `npx`, or any other Node.js package manager.

### Node.js Package Installation
- Use `bun install` instead of `npm install`
- Use `bun add <package>` instead of `npm install <package>`
- Use `bun add -d <package>` for dev dependencies
- Use `bun remove <package>` instead of `npm uninstall`

### Node.js Scripts
- Use `bun run <script>` instead of `npm run <script>`
- Use `bun <file.js>` to execute JavaScript/TypeScript files directly
- Use `bunx` instead of `npx` for one-off command execution

### Node.js Dependency Management
- Use `package.json` for project configuration
- Use `bun.lockb` for lockfile (binary format, auto-generated)
- Always use `bun install` after modifying `package.json`

### Docker/CI/CD
- Install bun via official installer: `curl -fsSL https://bun.sh/install | bash`
- Use `bun install` in Dockerfiles
- Never use `npm install`, `yarn install`, or `pnpm install`

### Examples
```bash
# ✅ CORRECT
bun install
bun add express
bun add -d @types/node
bun run dev
bunx vite build

# ❌ WRONG
npm install
yarn add express
pnpm install
npx vite build
```

## Summary

- **Python**: `uv` ONLY - no pip, poetry, conda, etc.
- **Node.js**: `bun` ONLY - no npm, pnpm, yarn, npx, etc.
- These rules apply to ALL contexts: local development, Docker, CI/CD, scripts, documentation, and examples.
